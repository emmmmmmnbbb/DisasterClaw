\section{Reproducibility and provenance}
\label{app:provenance}
\subsection{Inputs and reproduction boundary}
The manuscript uses a single principal offline population and two online shards. The offline source directory is \path{runs/benchmarks/paper_cja_mech_v1/}. Paired evaluation predictions are read explicitly from \path{final_fov/fov_ladder_eval_items.jsonl}; development pairs come from \path{fov_ladder_val_items.jsonl}; the reported allocation curves are in \path{budget_allocation.json}. This explicit selection prevents a missing evaluation filename from silently causing a fallback to development results.

The online records are \path{episodes.jsonl} in two shard directories beneath \path{runs/benchmarks/cja_agent_vqa/}. Their shared directory-name prefix is \path{paper_cja_mech_final_shard}, followed by \texttt{0of2} or \texttt{1of2}. Each configuration/question key must occur once, and each configuration must contain the same 160 question IDs. Recorded correctness is recomputed as a count of the archived flags; this operation does not reannotate images or regenerate model answers.

The local scripts \path{cja_en/scripts/audit_downloaded_results.py} and \path{cja_en/scripts/build_assets.py} read these inputs without modifying them or invoking a model. They regenerate the audit, additional analyses, six tables, and two quantitative plots. The audit records input byte counts and full SHA-256 values. The asset generator rejects changed audited inputs and verifies the allocation reconstruction used by the bootstrap. The overview diagram is a schematic of the implemented evaluation, not a synthetic experimental observation.

The paired-building recomputation matches all seven allocation curves at five budgets for accuracy, macro-F1, ECE, Brier score, NLL, executed selections, and net corrections to an absolute tolerance of $10^{-9}$. Final three-view metrics also reproduce to that tolerance. These checks establish numerical consistency of available records. They do not certify that the runtime model, original images, or evaluation history can yet be independently recovered.

\subsection{Remaining execution requirements}
The frozen manifest was generated on 26 August 2026. Both online shard manifests identify source commit \texttt{cfb5c827} (abbreviated) and mark the working tree as dirty. The audit retains its full hash. The currently inspected source is a later revision. Exact reproduction therefore requires the uncommitted runtime changes or an archived source tree, in addition to the named commit. Empty language- and vision-language-model fields must be resolved from contemporaneous logs or author records, rather than filled from current defaults.

The frozen question set and dataset entities are needed to verify their manifest hashes, target construction, scoring rules, and relationships between selection and final populations. Checkpoint files and training manifests are needed to characterize perception exposure directly. Although an additional archive identifies a different event-disjoint perception backend, those results are not combined with the principal tables here: changing the backbone changes the experiment, and its checkpoint provenance remains to be verified.

The online run history also requires repair or regeneration of reference-dependent controls. A safe rerun should bind each dependent episode to the reference question ID, reference action budget, reference result hash, source snapshot, model configuration, and prompt hash. Resuming a completed episode should require those identifiers to match. All configurations should retain requested, allocated, and executed budgets, rather than relying on a single final action total. This is a proposed evaluation correction, not a claim that the existing records satisfy it.
