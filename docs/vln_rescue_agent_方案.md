# 做一个"听人话飞、会找灾情"的无人机 Agent —— 方案说明（大白话版）

本文用尽量简单的话，讲清楚三件事：
1. DisasterClaw 现在是什么、还差什么；
2. 我们想抄的几篇论文（CityNavAgent、STMR、CityNav、LM-Nav）各做了什么、我们拿它哪一块；
3. 我们打算怎么一步步做，以及怎么证明它有用。

> 一句话目标：让无人机能**听懂一句中文/英文指令**（比如"去北边看看有没有完全塌掉的房子"），
> 自己**飞过去、看清楚、给出判断**，专门用在**灾后救援巡查**上。

---

## 1. 现在的 DisasterClaw 是什么

打个比方：现在的系统像一个**在卫星地图上飞的玩具无人机 + 一个会看图的助手**。

- **地图**：用真实卫星底图，叠上灾害数据集（xBD / RescueNet）的航拍图，每张图都知道自己在地球上的真实经纬度。
- **看图能力**（感知）：无人机飞到哪，就把那块地图裁下来，用 YOLO（认 6 类东西：完好/轻微/严重/完全损毁的房子、车辆、积水）+ 分割模型，给出"这片区域灾情多重"。
- **两种"会飞"的方式**：
  - 老方式：你给一句任务，大模型一次性写好"先飞到这、再看、再报告"的步骤清单。
  - 新方式（已有雏形）：你给一句指令，无人机**一步步**地——看一眼 → 判断目标在不在画面里、在哪 → 朝目标挪一点 → 直到目标到了画面中间算"到达"。

**重点**：我们这套是"**在俯视地图上按语言找目标**"，不是真正的"第一视角开飞机"。这点决定了论文该抄哪些、不该抄哪些（见第 3 节）。

---

## 2. 现在还差什么（短板）

用大白话列，按重要性排：

1. **看不准**：YOLO 只认 6 类，而且它是在航拍图上训的，换到卫星图就"水土不服"，很多东西看漏。开放词汇模型（什么都能找的那种）实测也偏弱（见第 4 节）。
2. **没记性**：每次任务都是"一张白纸"，飞过的地方、看到的东西，任务一结束就忘了。找不到目标时只会**机械地绕方块螺旋**地毯式搜，不会动脑子。
3. **不会拆任务**：指令稍微长一点、有好几个地点（"先到 A，再到 B，最后停在 C"），就容易懵。现在靠**关键词硬匹配**，很脆。
4. **灾情判断没用到飞行决策上**：系统其实算了"这片灾情多重"，但**没拿这个去指挥飞行**（比如"这栋楼看不太清、灾情可疑，飞近点再确认一下"）。这恰恰是我们最想做的创新点。
5. **没有成绩单**：没有标准的"导航成功率"评测，也没有专门的测试题库。没成绩单，论文就站不住。

---

## 3. 四篇论文，我们各抄一块（不照搬任何一篇）

先记住一个判断标准：我们是 **2D 俯视 + 知道真实经纬度**。所以凡是依赖"第一视角、深度相机、3D 点云"的部分，我们都**不抄**，因为我们有更省事的地理坐标可用。

### 论文 A：CityNavAgent —— 我们抄它的"**怎么思考、怎么记路**"

它把"开飞机"拆成三层来想，从粗到细：
- **第一层（找地标）**：把长指令拆成一串地标，"先到加油站 → 再到带树的广场 → 最后到白房子"。
- **第二层（常识推理）**：看不到下一个地标时，用大模型的常识猜"那我先往哪去"。比如要找红绿灯，眼前只有楼和马路，常识告诉它"红绿灯一般在马路边，先往马路去"。
- **第三层（具体怎么飞）**：把上面的决定变成实际航点和动作。

另外它有个**记忆地图**：把以前成功走过的路存成一张"地点网络图"，下次走熟路就直接查图，不用重新摸索。

> **我们拿走**：这套"拆地标 → 常识推理 → 出航点"的三层思路（用来替换我们脆弱的关键词匹配），
> 以及"记忆地图"（降成 2D 版，正好更简单）。
> **我们丢掉**：它的 3D 语义点云（要深度相机，我们不需要）。

### 论文 B：STMR —— 我们抄它的"**怎么把地图喂给大模型**"

它发现一个很实用的点：**直接把地图图片丢给大模型看，效果差；把地图变成一张"文字表格"再喂，效果好很多。**

具体做法：把无人机周围 100m×100m 切成 20×20 的小格子，每格 5m，每格只写一个标签（比如"楼""车""空地"），再告诉模型每格多大。这样大模型就能像看棋盘一样推理"目标在我东边第几格"。

> **我们拿走**：这个"地图变文字表格"的技巧——而且我们比它还省，
> 因为我们有真实经纬度，直接就能生成这种带坐标的表格，连深度反投影都不用。
> 这能直接改善我们现在"把图片丢给大模型问目标在哪"召回不稳的问题。

### 论文 C：CityNav —— 我们抄它的"**地图该画哪些层 + 救灾怎么测**"

它做了真实城市的航拍导航数据集，并提出一张**地理语义地图**，分 5 层：当前视野 / 已探索区 / 地标 / 可能的目的地 / 周围物体。加上这张图后，导航成功率明显提升。

最关键的是：**它专门测了"洪水、地震、GPS 信号不可靠"情况下还能不能导航。**

> **我们拿走**：这 5 层地图的"图层清单"直接当我们地图的设计规范；
> 它的"洪水/地震/GPS 退化"鲁棒性测试，直接搬来当我们的**评测方案**——
> 这正好是我们救灾主题的差异化卖点，也补上了我们"没有成绩单"的短板。

### 论文 D：LM-Nav —— 我们抄它的"**记忆地图怎么查**"

它不训练任何模型，直接拼三个现成的：大模型拆地标、CLIP（看图配文字的模型）判断"这张图是不是这个地标"、再用一个**图搜索算法**在地点网络里找出最优路线。

> **我们拿走**：它的"图搜索算法 + 用打分判断某地点是不是某地标"，
> 当作我们记忆地图的查询方式（CityNavAgent 的记忆图其实也是借它的）。

## 4. 关于"什么都能找"的开放词汇模型：实测告诉我们别迷信它

我们实测了 NVIDIA 的 LocateAnything-3B（一个号称"给个词就能在图里框出来"的开放词汇模型），在 RescueNet 航拍验证集（198 条）上：

- 总体 F1@0.5 只有 **0.14**（很弱）；
- 但**车辆能到 0.67、完好房子 0.31**（常见、长得像普通照片的东西还行）；
- **损伤分级（轻微/严重/完全损毁）很差**——通用模型不懂"灾害专业语义"；
- 而且**爱乱框**（精确率低），单张要 5.4 秒、占 20GB 显存。

**结论（写进选型）**：开放词汇模型不是万能钥匙。打算用 **混合策略**：
- 常见目标（车、房子）优先用域内训练过的 YOLO（快、准）；
- YOLO 认不出的、或指令里出现的新词，再用开放词汇模型兜底；
- 后续用 prompt/LoRA 给开放词汇模型补"灾害专业语义"。

## 5. 我们的卖点（和这四篇的区别）

这四篇都在做"城市里按指令飞到某地"。**没有一篇**把它做到**灾后判读**上。

> 我们的差异化：**"会看灾情"的语言导航**——
> 不只是飞到目标，而是**用"灾情判断的把握程度"来指挥飞行**：
> 没把握就主动飞近、换角度再确认一遍。这就是我们之前定的创新主线（C2）。

---

## 6. 怎么一步步做（落地三步）

沿用已有调研里"对照组 / 中间组 / 创新组"的实验框架，把上面四篇的精华塞进去：

- **第 0 步（打地基）**：建一张**会一直累积的 2D 地理语义地图**（按 CityNav 的 5 层规范画），记下飞过哪、看到啥。
- **第 1 步（最划算，先做）**：
  - 用 **STMR 的"文字表格"** 把地图喂给大模型；
  - 用 **CityNavAgent 的三层思路（拆地标→常识推理→出航点）** 替换现在脆弱的关键词匹配。
  - → 立竿见影地提升"听长指令、会找目标"的能力。
- **第 2 步（创新主线）**：
  - 把"灾情把握程度"接进飞行决策——**没把握就飞近复核**；
  - 加上 **2D 记忆地图 + LM-Nav 图搜索**，支持大范围、长距离巡查。

视觉路线决定：**先把"俯视地图 + 语言"这条路做出论文级结果**，"真·第一视角开飞机"列为以后的工作。

---

## 7. 怎么证明它有用（评测）

照搬 CityNav 的成熟做法，补上我们现在缺的成绩单：

- **标准导航指标**：成功率（SR）、路径效率（SPL）、离目标多远（NE）。
- **救灾专属测试**（差异化）：模拟**洪水/地震**场景、模拟 **GPS 不准**，看还能不能稳。
- **我们独有的**：灾情判断"把握程度"随飞行的提升速度、单位飞行代价能确认多少个目标。
- 需要准备一个小的"**指令 → 正确轨迹**"测试题库（目前没有，要做）。

## 附：名词小抄

- **VLN（视觉语言导航）**：让机器"听一句话 + 看画面"自己走到目标。
- **grounding（目标定位）**：把指令里的词，对应到画面里具体哪个框。
- **开放词汇**：不限定类别，给任意一个词都能去找（对比 YOLO 只认固定几类）。
- **拓扑/记忆地图**：把走过的地点连成一张"地铁线路图"，方便复用熟路。
- **NBV（下一最佳观测点）**：下一步该飞哪看，信息收益最大。
- **SR / SPL / NE**：导航领域的三个标准打分（成功率 / 路径效率 / 离目标的距离误差）。
